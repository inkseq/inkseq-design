v6 additions: editProject(mutator,options) atomically validates and commits cloned project data, catches errors without partial change, and supports undo. Character data.looks holds named gallery/version records; scene and shot data.cast bind per-character look IDs, with shot overrides resolved per character. Shot data.referenceRanges[linkId] stores explicit trims and source-file snapshots; candidateIds, uxReview.issues/allRejected, and acceptPlaceholder represent review decisions. journey.breakdown and import receipts retain original script and reversible confirmed batches. journey.soundTracks[chapterId] stores trimmed source audio, relative shot origin, offset, gain and mute. journey.delivery stores delivery preferences; return-to-check coordinates and character focus are presentation state. Complete backup remaps reference-range and sound-track file snapshots with media IDs. Direct shot content edits require candidate review; accepted placeholders must be renewed after content changes. UI modules own their explicit cross-entity change rules; ordinary identity edits propagate to effectively cast shots. See ../../UX-V6-ITERATIONS.zh-CN.md and latest ../../UX-REVIEW.zh-CN.md.

v5 UX additions: snapshot.section also accepts journey and new projects start there. store.updateProject({title,logline,journey}, options) preserves identity and allows non-history preview-position updates. Optional project.journey stores stage (integer 1–7), brief (entry/audience/aspect/seconds/sourceScript), sound (mode/dialogue/music/subtitles), reviewShotId, scriptImport (source/chapterId), and preview (chapterId/shotId). shot.data.uxReview stores demo candidate A/B, revision note and demonstration status. Example A/B selections are explicitly prototype examples, never model outputs or jobs. Selecting an example clears selectedAssetId; selecting an existing asset clears uxReview.chosen, retaining revision notes and the underlying media asset. This keeps the active candidate unambiguous across review and preview. Imported older conflicting state resolves to the existing asset until an explicit new choice. An upstream shot.status='review' preserves selection until the user confirms that shot again. CreationJourney uses the same chapter/scene/shot entities and typed references as Canvas; stage navigation is not a separate copy of the story. Delivery is a real downloadable non-executable JSON plan, not rendered media. See ../../UX-REVIEW.zh-CN.md for tested scope and remaining UX.

v4 delivery additions: store.updateProject({title,logline}) edits metadata without replacing selection/history. store.getRecoveryRaw() returns protected original text for explicit recovery download. Media data.missingFile is a local availability flag; retain entity IDs/references when missing and never treat a file ID alone as usable media. findMissingFileIds(project) checks IndexedDB keys, not decodability, and rejects storage errors. Provider execution, cloud persistence and collaboration are not implemented. See ../../ITERATION-REPORT.zh-CN.md for current scope.
